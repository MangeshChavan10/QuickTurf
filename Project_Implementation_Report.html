Project Implementation Report

Project Name: QuickTurf - Solapur's Premium Turf Booking Platform

Architecture: MERN Stack (MongoDB, Express, React, Node.js)

Developed by: Mangesh Chavan & Team

1. Executive Summary

QuickTurf is a full-stack web application designed to streamline the sports turf booking process in Solapur. It provides a three-tier architecture supporting Users (Players), Admins (Turf Owners), and SuperAdmins (Platform Moderators). The system features real-time slot availability, secure payment processing via Razorpay, and automated notification systems.

React 19 TypeScript Node.js Express MongoDB Razorpay API Nodemailer Tailwind CSS Framer Motion

2. System Architecture

The project follows a modular Client-Server architecture:

  • Frontend: A Single Page Application (SPA) built with Vite and React, utilizing Context API for state management and Framer Motion for premium animations.
  • Backend: A RESTful API built with Node.js and Express, using Mongoose for MongoDB object modeling.
  • Security: Implemented using JWT authentication, Bcrypt password hashing, Helmet for HTTP headers, and Rate Limiting to prevent DDoS/Brute-force attacks.

3. Backend Implementation (The Engine)

The backend handles all business logic, database interactions, and third-party integrations.

backend/server.ts

The central hub of the application. It contains API route definitions, middleware configuration (CORS, body-parser), and the Cron Job system that automatically releases expired booking locks and sends 1-hour match reminders.

backend/models/
  • User.js: Stores user profiles, roles (user/admin/superadmin), and moderation status (banned/warnings).
  • Turf.js: Detailed turf data including location, pricing, facilities, and owner mapping.
  • Booking.js: Tracks transaction IDs, slot times, and refund statuses.
  • Otp.js: Temporary storage for 2FA/Login verification codes.
backend/services/
  • email.service.js: Handles SMTP configuration for sending transactional emails (OTPs, Booking Confirmations, Reminders).
  • razorpay.service.js: Initializes the Razorpay SDK for payment capturing and automated refunds.

Key Feature: The Booking Pipeline

1. Slot Locking: When a user selects a slot, the system creates a Pending booking to "lock" the slot for 10 minutes.

2. Payment: Razorpay processes the transaction. The backend verifies the cryptographic signature to prevent fraud.

3. Confirmation: Upon success, the status changes to Confirmed and an automated email is sent.

4. Auto-Release: If payment isn't completed within 5 mins, a Cron Job releases the lock.

4. Frontend Implementation (The Experience)

The frontend focuses on a "Premium Sports" aesthetic with a mobile-first approach.

frontend/src/App.tsx

Main router using react-router-dom. Implements Route Guards (ProtectedRoute, AdminRoute) to ensure only authorized users access sensitive pages.

frontend/src/pages/
  • Home.tsx & Explore.tsx: Interactive search and discovery for turfs.
  • TurfDetail.tsx: Dynamic slot selection engine and review system.
  • Checkout.tsx: Integration with Razorpay Checkout UI.
  • admin/Dashboard.tsx: Business analytics for turf owners (Revenue, Booking Trends).
  • superadmin/PartnerApprovals.tsx: Platform-wide control for approving new turf owners.
frontend/src/contexts/AuthContext.tsx

Manages global user state, JWT persistence in LocalStorage, and handles the Login/Logout logic.

5. Security & Reliability

Feature Implementation
Authentication JWT (JSON Web Tokens) with 30-day expiry. Support for Google OAuth.
Payment Security HMAC-SHA256 signature verification for all Razorpay callbacks.
Data Protection express-mongo-sanitize to prevent NoSQL Injection.
Rate Limiting express-rate-limit applied to Login and Payment endpoints.
Reliability Background Cron Jobs for cleanup and automated reminders.

6. Deployment

  • Frontend: Hosted on Vercel for global CDN delivery and performance.
  • Backend: Deployed on Render using a Node.js runtime.
  • Database: Managed MongoDB Atlas cluster with automated backups.
